## 目的

PR #44 で追加した「本 skill の実行で完了するタスク行」の検出に、対象外指定が無いという穴を塞ぐ（Issue #45）。兄弟プロジェクト slapex で同じ取り込みを行った際に AI reviewer から入った指摘を反映する。

## 現在の状況

- `.agents/skills/number-working-branch-note/SKILL.md` の Step 5 に、対象外タスクの明示と複合行の扱いを追加した。
- 非 checkbox 行の書き換え形式を `（完了）` の付記のみへ確定し、行を削除しない理由を添えた。
- 「終了時の報告」の分類を、定型外・複合行・判断不能の 3 種へ揃えた。
- review 指摘 3 件（`[must]` 1 / `[imo]` 2）を採用し、完了判定の基準、報告分類、Step 10 の継承範囲を追記した。

## 決定事項

- `progress.md` の PR 番号反映は本 skill の完了対象に含めない。Step 7 が commit 対象を `working-branch-notes/` 配下に限定しており、索引更新は `doc/guidelines/issue-driven-task-execution.md` の step 7 が担う別手順である。
- 1 行に完了する要素と完了しない要素が混在する行は、行全体を完了扱いにせず触らず報告する。未完了の部分が隠れるため。
- 「実際の反映を確認できた場合だけ完了化する」案は採らない。`progress.md` の状態確認 step が必要になり、本 skill の責務（ファイル名規約切り替え時点の整合取り）を超える。触らず報告する扱いなら既存の一般則と同じ収束先になる。
- 非 checkbox 行は行末に `（完了）` を付け、削除しない。bizdate の既存 note は `## 次にやること` に checkbox を使っておらず実際に通るのはこの経路であり、分岐を残す必要がない。note は作業ログなので、採番時点で何が完了していたかを消さない方が後から辿れる。
- ユーザー合意 gate は維持する。slapex は過去の経緯から gate を外して定型置換へ寄せているが、bizdate は PR #44 の判断を変えない。
- decision log は作らない。skill 手順の調整であり、PR #44 と同じ扱いとする。tool 名の方針（0017）は今回の対象外。
- Step 10 は対象外指定を定義として継承するが、複合行の処置規定までは継承されない。review 指摘を受け、Step 10 に 1 句を追記した。
- 完了かどうかの判定基準は「本 skill の終了時点で未完のまま残るか」とする。PR の作成のように前提条件として実行前に満たされている要素は完了として扱う。これが無いと、Step 5 が書き換え対象の代表例に挙げる「PR を作成し、note を採番する」自体が複合行として書き換え禁止側に落ち、主経路が決まらない。
- 検出対象の定義も「本 skill の実行で完了するタスク行」から「本 skill の終了時点で完了しているタスク行」へ揃える。前者のままだと、前提条件だけで構成された行（「PR を作成する」単独など）が判定基準では完了なのに検出対象にも複合行にも入らず、黙って stale のまま残る。Step 10 と複合行の表現も同じ語へ合わせる。
