# 業務日・日付・祝日

この文書は、`bizdate` の日付扱い、業務日の定義、祝日データの正本である。

想定読者は、仕様を実装・検証する開発者と AI agent である。

CLI の option と exit code は `cli-interface.md` を参照する。決定経緯は `decision-log/0004-date-and-timezone.md`、`decision-log/0005-business-day-definition.md`、`decision-log/0006-holiday-data-source.md`、`decision-log/0008-language-and-distribution.md` を参照する。

## 日付とタイムゾーン

- 判定対象はカレンダー日付のみとする。時刻は扱わない
- 「その月」は、指定日が属する暦月とする
- 日付の入力形式は `YYYY-MM-DD` のみとする
- 日付を省略した場合の「今日」は、採用するタイムゾーンにおける暦日とする
- タイムゾーンの既定は、実行環境の local timezone とする
- タイムゾーンの上書き経路と優先順位は次とする
  1. CLI option `--timezone`（IANA 名）
  2. 環境変数 `BIZDATE_TZ`（IANA 名）
  3. local timezone
- プロセス全体の `TZ` は、bizdate 専用の指定手段としては採用しない（local timezone の解釈には OS / ランタイムの通常規則が効いてよい）
- 不正な日付（存在しない日、形式不正）、未知のタイムゾーンはエラーとする
- 採用するタイムゾーン指定の空文字は未知の名前としてエラーにする。`BIZDATE_TZ` の空文字と未設定は区別し、上位の指定を採用した場合は下位の値を検査しない
- ローカル祝日データが無い、期限切れ、または指定日の年をカバーしない場合はエラーとする。土日だけで判定して成功させない

## 業務日の定義

業務日は、次のすべてを満たす日とする。

1. 月曜日から金曜日である
2. 日本の国民の祝日でない（ローカルに保存された祝日データに含まれない）
3. 利用者指定休日（`--day-off`）でない

補足:

- 土曜日と日曜日は休日とする
- 振替休日および国民の休日は休日とする
- ローカル祝日データに載る日付は、自前で祝日法を再計算せず休日とする
- ツール既定として、法定外の年末年始・夏季休暇・会社固有休日を埋め込まない。したがって `--day-off` が無ければ、元日以外の 12/29–1/3 などは業務日になり得る
- v1 の既定の取得先は日本の国民の祝日 CSV とする。他国は将来、取得先 URL の差し替えで拡張する想定とする

## 利用者指定休日

- CLI option `--day-off` にカンマ区切りの日付リストで与える
- 範囲指定は扱わない
- 各要素の形式は `YYYY-MM-DD`、または年を省略した `MM-DD` とする
- `MM-DD` の年は、採用タイムゾーンにおける「今日」の年とする
- 不正な要素（形式不正、存在しない日、空要素）はエラーとする
- `--day-off` はローカル祝日データの取得・保存・expire の対象外とする

## 月の最初 / 最後の業務日

- ある月の最初の業務日は、その月に属する業務日のうち最も早い日とする
- ある月の最後の業務日は、その月に属する業務日のうち最も遅い日とする
- 業務日が1日しかない月では、その日が最初かつ最後の業務日になる
- `first` 判定と `last` 判定は独立である。同一日が両方に該当し得る

## 祝日データ

- 祝日データの取得・更新はサブコマンド `fetch-holidays` が行う
- `fetch-holidays` はインターネット上の情報源から祝日データを取得し、ローカルに保存する
- 判定サブコマンド（`first` / `last`）はローカルに保存された祝日データだけを読む。実行時にネット取得しない
- ローカルデータが無い場合、判定はエラーとする
- ローカルデータの有効期間は取得時から1年とする。expire したデータは無効とし、存在しない状態として扱う
- 取得先は `--source` で指定する
- `--source` 未指定時の既定 URL は `https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv` とする（案内: https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html）
- CSV に掲載される日付（振替休日を含む）を祝日（休日）とする
- 日本以外の祝日へ拡張する場合は、`--source` にインターネット上の任意 CSV URL を指定することを想定する。対象国・CSV スキーマの詳細は未決とする
- ローカル保存場所は `$XDG_DATA_HOME/bizdate/holidays/holidays.csv` とする。`XDG_DATA_HOME` 未設定時は `~/.local/share/bizdate/holidays/holidays.csv` とする
- 保存先の基点は絶対 path とする。`XDG_DATA_HOME` の空文字・相対 path はエラーとし、未設定時だけ `HOME` を使う。必要な `HOME` が未設定・空文字・相対 path の場合もエラーとする
- ローカルファイルは UTF-8 の CSV とする。取得元が Shift_JIS / CP932 等の場合は保存時に UTF-8 へ変換する
- bizdate 用メタデータは同一ファイル先頭の `#` 行に埋め込む。少なくとも `schema`、`fetched_at`（UTC RFC 3339）、`source_url` を記録する。`expires_at` を書いてよい（省略時は `fetched_at + 1 year`）
- メタ行の直後に、UTF-8 化した取得元 CSV の本文（ヘッダとデータ行）を続ける。判定時は先頭の `#` 行をスキップしてから CSV を読む
- 実装では外部 holiday ライブラリに寄せず、取得した CSV を自前で解釈する。詳細は [0009](decision-log/0009-holiday-csv-local-format.md)

### ローカル読み取りの境界

- schema `1` のメタ行は `# bizdate-meta schema=1`、`# fetched_at=<日時>`、`# source_url=<URL>`、任意の `# expires_at=<日時>` とする。既知フィールドの重複、必須フィールドの欠落・空値、未対応 schema はエラーとする。未知の先頭 `#` 行は読み飛ばす
- `fetched_at` と `expires_at` は UTC の RFC 3339 とする。`Z` または `+00:00`、秒の小数部を扱う
- `expires_at` があれば優先する。省略時は UTC 上で `fetched_at` に暦年を 1 年加算し、時刻を維持する。2 月 29 日は翌年の 2 月末に丸める
- 現在時刻が有効期限以上になった時点で expire とする。ファイルを削除せず、欠落と同様に判定をエラーにする
- v1 の本文は `国民の祝日・休日月日,国民の祝日・休日名称` の 2 列とし、日付は `YYYY/M/D`（月・日のゼロ埋めも可）で読む。日付の重複は集合にまとめる。ヘッダ不一致、列数不一致、不正日付、日付が 0 件の本文はエラーとする
- 年カバーは本文の日付の最小年から最大年まで（両端を含む）とする。祝日照会では対象年と有効期限を検査し、年カバー外や期限切れを「祝日ではない」として扱わない

## v1 で扱わないこと

- 埋め込み会社カレンダーや、設定ファイルによる休日集合の本格対応
- option 既定をコンフィグファイルで上書きする仕組み（例: `--config`、`~/.config/bizdate/options`）
- 翌営業日 / 前営業日 / 第 N 営業日 / 営業日数
- 日本以外の祝日カレンダーの本格サポート（`--source` 差し替え想定のみ記録）
