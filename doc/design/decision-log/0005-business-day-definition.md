# 業務日の定義

- 状態: decided
- 作成日: 2026-09-06
- 最終更新日: 2026-09-06
- 関連: `doc/design/business-day.md`, `doc/design/cli-interface.md`, `doc/design/decision-log/0003-v1-scope.md`

## 背景

コンセプトの未決の中心である。土日・祝日・振替休日・会社の年末年始をどこまで休日にするかを誤ると、年末年始や連休でゲートが誤判定する。一方で、利用者が毎年決まった法定外休日を足したい需要もある。

## 候補

- A: 月〜金かつ日本の国民の祝日でない日を業務日とする。振替休日・国民の休日は祝日カレンダーに載るものを休日とする。会社の法定外休日は v1 対象外
- B: 土曜出勤を想定し、日曜と祝日だけを休日とする
- C: よくある会社の年末年始（例: 12/29–1/3）を v1 の既定休日に含める
- D（採用寄り）: A をベースにしつつ、利用者が休日と定める日を CLI option の日付リストで追加できる

## 検討内容

多くの日本の事務・システム運用では土日を休日とする。土曜出勤を既定にすると、一般的な「業務日」直観とずれる。

振替休日・国民の休日は内閣府の国民の祝日カレンダーに載る。自前で祝日法を再計算するより、カレンダー掲載分を休日とする方が単純で誤判定しにくい。

会社の年末年始をツール既定に含めると組織差を固定してしまう。一方、利用者がその場で休日を足せる経路があれば、既定は法定寄りに保ったまま年末年始などを扱える。

日付リストは範囲指定より誤用が少なく、実装も単純である。年の省略は毎年同じ月日を繰り返し指定しやすくする。省略時の年は、日付方針（0004）で決めた採用タイムゾーンにおける「今日」の年とする。

設定ファイル（`--config` や `~/.config/bizdate/options`）で option 既定を上書きする構想はあるが、v1 には含めない。タイムゾーン指定も同様に、将来は config から与えられる想定とする。

業務日が1日しかない月では、その日が最初かつ最後の業務日になる。`--first` と `--last` は独立に yes になり得る。

## 決定

- 業務日は、次のすべてを満たす日とする
  1. 月曜日から金曜日である
  2. 日本の国民の祝日でない
  3. 利用者指定休日でない
- 振替休日および国民の休日は休日とする。内閣府カレンダーに載るものは自前再計算しない
- 土曜日は休日とする
- ツール既定として、法定外の年末年始・夏季休暇・会社固有休日を埋め込まない。したがって指定がなければ、元日以外の 12/29–1/3 などは業務日になり得る
- 利用者指定休日を v1 で扱う。指定は CLI option `--day-off` とする
- `--day-off` の値はカンマ区切りの日付リストとする。範囲指定は扱わない
- 各要素の形式は `YYYY-MM-DD`、または年を省略した `MM-DD` とする
- `MM-DD` の年は、採用タイムゾーンにおける「今日」の年とする（0004 のタイムゾーン解決後の「今日」）
- 不正な要素（形式不正、存在しない日、空要素）はエラーとする
- ある日が、その月の最初の業務日かつ最後の業務日になり得る。`first` と `last` は独立に yes になり得る
- option 既定をコンフィグファイルで上書きする仕組み（例: `--config`、`~/.config/bizdate/options`）は将来構想として記録し、v1 には含めない

## 理由

法定カレンダーを既定にしつつ、必要な法定外休日だけを明示リストで足せると、組織差をツール既定に混ぜずに実務へ寄せられるため。範囲や設定ファイルは v1 の複雑さに見合わない。

## 影響

- 0003 の「会社固有休日は v1 対象外」は、設定ファイルや埋め込み会社カレンダーを指す。CLI の日付リストによる利用者指定休日は v1 対象とする（0003 に追記する）
- 業務日仕様に定義と `--day-off` の解釈を書く
- CLI 仕様に `--day-off` を載せる
- コンフィグファイルは次点候補として `concept.md` と未決表に残す

## 後から見直す条件

- 土曜出勤を既定にする業界向けモードが必要になった場合
- 日付範囲や繰り返し規則（毎年）の専用記法が必要になった場合
- コンフィグファイルによる option 既定上書きを v1 以降で実装する場合
- 祝日カレンダーに載らない臨時休日を、利用者指定以外の経路で扱う必要が出た場合

## 追記 (2026-09-06)

CLI 検討（0007）で、option 名を仮の `--holiday` から `--day-off` へ変更した。国民の祝日データ（`fetch-holidays` / `--source`）と語が衝突するためである。意味（利用者指定の休み日）は変えない。
