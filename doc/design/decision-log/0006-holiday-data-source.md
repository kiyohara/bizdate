# 祝日データ源と更新

- 状態: decided
- 作成日: 2026-09-06
- 最終更新日: 2026-09-06
- 関連: `doc/design/business-day.md`, `doc/design/cli-interface.md`, `doc/design/decision-log/0003-v1-scope.md`, `doc/design/decision-log/0009-holiday-csv-local-format.md`

## 背景

業務日定義が国民の祝日に依存するため、何を正本とし、どう取得・保存し、古くなったデータをどう扱うかを決める必要がある。当初案はバイナリ同梱だったが、更新を利用者が明示的に行い、将来は取得先 URL を差し替えて他国 CSV にも広げたい、という方針に寄せる。

## 候補

- A: 正本を内閣府「国民の祝日」CSV とし、配布物に同梱。実行時ネット取得なし。保証年は同梱範囲。更新はリリースで配る
- B: 判定コマンド実行時に都度ネット取得する
- C: holiday_jp などの派生データや外部ライブラリを正本にする
- D（採用）: 取得専用サブコマンドがネット上の情報源から取得してローカル保存する。判定はローカルのみを読む。欠落・期限切れはエラー。取得先は option で指定し、既定は内閣府 CSV

## 検討内容

ゲート用途の判定コマンドがネットに依存すると、オフラインや一時障害で月次ジョブが落ちる。取得を明示サブコマンドに分離すれば、判定側はローカルファイルの有無だけを見ればよい。

バイナリ同梱は再現性は高いが、祝日追加のたびに再配布が必要になる。ローカル保存＋利用者が更新する形なら、ツール本体のリリースと祝日更新を分離できる。

有効期間を1年とし、expire 後は存在しないものとして扱うと、古い祝日データのまま誤判定し続けるリスクを抑えられる。破棄は「無効として扱った結果、データが無い状態と同じ」とする。

取得先を option にすると、既定は内閣府 CSV のまま、将来の他国対応ではインターネット上の任意 CSV URL を指定する拡張ができる（0003 の将来候補と整合する）。

CSV の具体レイアウトやローカル保存パスの最終形は、実装言語・CLI 詳細と合わせて詰めてよいが、方針として XDG 風のユーザデータ配置を想定する。

## 決定

- 祝日データの取得・更新は、判定用の root 実行とは別のサブコマンドで行う。仮の名前は `bizdate fetch-holidays` とする（正式名は CLI テーマで確定してよい）
- 当該サブコマンドは、インターネット上の情報源から祝日データを取得し、ローカルに保存する
- 判定コマンド（`--first` / `--last`）はローカルに保存された祝日データだけを読む。実行時にネット取得しない
- ローカルデータが無い場合、判定コマンドはエラーとする（土日だけで成功させない）
- ローカルデータの有効期間は取得時から1年とする。expire したデータは無効とし、存在しない状態として扱う（判定時は欠落と同じエラーになる。実装は削除しても無視してもよく、利用者から見た結果は同じにする）
- 祝日データの取得先は option で指定する。仮の名前は `--source` とする
- `--source` の既定値は、内閣府が公開する「国民の祝日」CSV の URL とする
- 日本以外の祝日へ拡張する場合は、この `--source` にインターネット上の任意 CSV URL を指定することを想定する。対象国・CSV スキーマの詳細は未決のまま残す
- 判定時に参照するローカルデータが、指定日の年をカバーしない場合もエラーとする
- 利用者指定休日（`--day-off`）はローカル祝日データとは別であり、本ログの取得・保存・expire の対象外とする

## 理由

判定の再現性・オフライン耐性を保ちつつ、祝日更新を利用者操作と取得先差し替えで扱えるため。他国対応の差し込み口にもなる。

## 影響

- 当初の「バイナリ同梱・実行時ネットなし」案は採用しない
- CLI は少なくとも祝日取得用のサブコマンドを持つ。テーマ5の「subcommand なし」下書きを修正する
- 実装言語テーマの `go:embed` 前提は外す。ローカルファイル I/O と HTTP 取得が必要になる
- 業務日仕様と CLI 仕様に、取得サブコマンド・ローカル保存・expire・`--source` を書く
- コンフィグファイルで `--source` 既定を上書きする構想は、他 option と同様に将来候補（v1 対象外）

## 後から見直す条件

- 内閣府 CSV の形式や公開 URL が大きく変わった場合
- 有効期間1年が短すぎる / 長すぎると分かった場合
- 判定コマンド側でもフォールバック取得が必要になった場合
- 他国 CSV のスキーマを正式サポートする場合
